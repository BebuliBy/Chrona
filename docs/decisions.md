## DEC-002 — первая аудитория и вход

- Дата: 2026-10-17. Статус: **принято пользователем**.
- Первая версия для себя и друзей, не обязательный Play-релиз. Вход через Telegram-бота с одноразовым подтверждением и возвратом в app.
- Начальные способы приглашения — ник/ссылка, телефон необязателен. Полный security protocol и recovery ещё проектируются.

## DEC-003 — первая метрика и порядок работ

- Дата: 2026-10-17. Статус: **принято пользователем**.
- Сначала проверить AccessibilityService на экране YouTube Shorts. Считать длительность открытого экрана, а не доказанное воспроизведение/внимание.
- Частные условия уточняются по эксперименту. Молчаливая замена Shorts общим временем YouTube недопустима. Detector, точность и supported matrix пока не подтверждены.
- Последующее выполнение 2026-10-17: базовый ручной проход на одном телефоне/версии дал положительный feasibility-результат; [фактический отчёт](spike-results-2026-10-17.md). Общая точность/совместимость/production readiness не подтверждены этим этапом.

## DEC-004 — друзья, индивидуальные права и интервалы

- Дата: 2026-10-17. Статус: **принято пользователем**.
- Взаимное подтверждение дружбы; настройки разрешённых активностей по каждому другу и defaults.
- Для разрешённых активностей друг видит те же данные/представления, включая начало/окончание интервалов. Это уточнение заменяет прежнее предложение ограничиться только дневными суммами; оно не было реализовано.
- Исторический scope, точность отображения и применение изменений defaults ещё открыты. Никакого доступа к токенам, системным настройкам или запрещённым типам.

- Дата: 2026-10-17. Статус: **принято общее направление**.
- Расширяемые активности, local-first/sync/restore, общая серверная логика app+bot, переносимый собственный backend, bot Telegram egress через требуемый proxy/VPN, простой onboarding.

## DEC-006 — исключить маленькое плавающее окно

- Дата: 2026-10-17. Статус: **принято пользователем**.
- Прямое решение: «Закрыл маленькое окно и не будем учитывать в таком окне просмотр shorts».
- Не учитывать просмотр Shorts в маленьком плавающем окне (SHORTS-003). Предыдущее предложение агента учитывать видимое floating-видео **не было принято**; оно не является требованием.
- В пройденном Home+маленькое окно current prototype уже останавливает учёт, поэтому код в этом эпизоде не менялся. Он анализирует active root; проверка исключения других focused/PiP/Samsung pop-up режимов ещё нужна (OPEN-WINDOW-MODES).
- Это не решение о времени предупреждения лимита: OPEN-OVERLAY остаётся отдельным открытым вопросом.

## DEC-007 — исключить предупреждение лимита

- Дата: 2026-10-17. Статус: **принято пользователем**.
- Явное подтверждение: «Время предупреждения тоже исключаем из просмотров».
- SHORTS-004: время предупреждения лимита не входит в Shorts. OPEN-OVERLAY о выборе этого правила закрыт; generic UNKNOWN/прочие overlays этим не классифицированы.
- В проверенной сцене prototype уже не начислял время, поэтому runtime-код не менялся. Надёжное различение неполноты наблюдения и других панелей — будущая работа.

## DEC-008 — название Chrona и Git

- Дата: 2026-10-17. Статус: **принято пользователем**.
- Первоначальное название MyChrona сразу уточнено на **Chrona**. Выбранное имя приложения/Gradle project — Chrona; каталог без отдельного запроса не переносился.
- Пользователь первоначально указал MyChrona.git, затем **явно заменил адрес на git@github.com:BebuliBy/Chrona.git** до первой отправки. Рабочая ветка **dev**, первоначальный push и постоянные осмысленные commit/push после согласованных изменений разрешены. На GitHub ничего самостоятельно не переименовываем.
- Подробный Git-порядок в AGENTS: только проверенные относящиеся файлы, без секретов/сборок/force, один корневой Git-писатель, проверка push. Разрешение не распространяется на другие проекты/deploy/APK-публикацию.
