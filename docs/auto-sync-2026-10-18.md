## Совместимый UI contract

В фактическом source существующий тип называется **SyncState**, не SyncUiState.
Добавлено последнее default-поле `automaticEnabled: Boolean = true`; UI читает
`state.sync.automaticEnabled`. Новый `ChronaAction.SetAutomaticSync(enabled)`
обрабатывается VM. Имена прежних state/actions сохранены, RequestSync остаётся
guarded «сейчас» без нового consent popup. При выключенном toggle raw upload не идёт,
в том числе через RequestSync. UI/preview/tests изменяет sibling, не этот child.

## Автоматика

- Toggle хранится в существующем DataStore, ключ — hash normalized target/account.
  Missing preference =true по новому явному user решению, включая действующий login
  при upgrade. Нет Room migration/purge, version остаётся4/0.3.2-ux.
- Login/restored own session, app startup и producer queue signals вызывают automatic
  controller. Собственный target/account/profile и auth session проверяются; другой
  profile не merge-ится, адрес/credentials не меняются. Disable паузит snapshot и
  отменяет on-demand work; logout очищает session обычным защищённым путём.
- Producer signal throttled10s, process loop30s с bounded backoff5..120s; не100ms
  sender. Один client mutex сериализует process/worker/explicit-now. Повторяющаяся
  automatic error не создаёт новый banner на каждом одинаковом retry.
- Snapshot membership теперь **внутренняя доставка**, не пользовательское согласие.
  На каждом automatic cycle транзакционный barrier может добавить текущие pending
  IDs в незавершённый own snapshot. В процессе отправки producer его не расширяет.
  Родитель внутри этого набора отправляется перед зависимой записью; отсутствующий
  parent не выдумывается. Frozen body/operationId/baseRevision не переписываются,
  replay идёт до pull, ACK/revision/cursor и source guards сохранены.
- За cycle не более100 raw sends/~90s send-loop. Остаток сохранён и повторяется
  следующим cycle, новые pending также попадут в последующий automatic barrier.
  Hard conflicts/rejections не LWW/не удаляются/не объявляются synced.
- Добавлен `androidx.work:work-runtime-ktx:2.10.1`, `AutomaticSyncWorker`/scheduler:
  unique on-demand KEEP, network CONNECTED, initial delay10s/backoff30s; unique
  periodic KEEP **минимум15min**. Work получает только app context, без URL/tokens
  в inputData. Worker читает действующую привязку/настройку заново. Внутрипроцессная
  сериализация shared client mutex; pending after slice → Work retry.
- Library manifest/startup обеспечивает WM wiring/network state/boot recovery;
  новый always-on/foreground daemon не вводился. Android Doze/quotas/network и
  force-stop не обходятся: background best effort, не обещание точного30s SLA.
  Social mutations явно заказаны отдельными actions и могут retry независимо от
  raw automatic toggle; они не открывают raw upload без его enabled/binding guards.

## Накопленное время и эмоция

- Automatic Shorts read model возвращает **Known recorded counter**, не «измерены
  все24часа». Нет intervals →0 записанных мс для текущего/прошлого дня. Отсутствующие
  manual entries остаются Unknown, future day не объявляется записанным0.
- ActualValue.Partial от collector для automatic habit оценивается по observedValue;
  score/emotion не блокируются только из-за partial coverage.7 ranges/q/cap/sign
  формулы сохранены. Измерений/ручного actual override не добавлено.
- Counter выбирает intervals/checkpoint конкретного DayKey/zone и только saved
  confirmed elapsed duration, не now-timer. Межсуточный stable-clock interval делит
  **имеющийся** ms budget по UTC overlap cumulative-floor differences; общий budget
  не растёт. История прошлого дня не получает current total другого дня.
- Gaps/segments остаются tech facts. Настоящая clock/day ambiguity и unresolved
  multi-device attribution не превращаются в invented duration. Нет destructive
  daily finalization/new daily table: цифры истории выводятся из сохранённых raw.
- Known0/zero-limit q=1 сохраняется. Zero-limit emotion/general normalized coefficient
  и absent goal не придумываются; UI вправе показать согласованный neutral fallback.
  Recurrence/streak/year/new activities/блокировка YouTube не добавлены.

## Known limits / root handoff

Root выполняет единственный assemble после sibling UI merge; здесь не было compile
или runtime verification новой WorkManager зависимости/wiring. Предыдущие tests
one-shot/partial-blocking соответствовали отменённой политике и намеренно не правились
ради green/не запускались. Нельзя выдавать прежние149 PASS за этот checkpoint.

Backend projection/валидация в этом scope не менялись: authorized friend snapshots
могут ещё вернуть прежние partial/Unavailable, а backend current-day-only manual
write policy/старые frozen rejections могут потребовать отдельного решения. Клиент
не сбрасывает операции и не меняет идемпотентный запрос, чтобы обойти такой reject.
Old ambiguous refresh/exchange всё ещё требует нового login по прежним security rules.
Во время disable невозможно «отозвать» уже начатый разрешённый HTTP request; новые
raw sends останавливаются, accepted/lost-response replay остаётся безопасным.

Никаких Root URL/credentials, actual vault/DB reads, Git/index, phone/ADB/server,
new agents/model checks, тестов/lint/сборок этим исполнителем не было.
