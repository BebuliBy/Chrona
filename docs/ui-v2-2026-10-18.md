Дата: **2026-10-18**. Поручение `chrona-ui-20261018`, child developer → root archi.
Рабочая копия: `/tmp/opencode/chrona-ui`. Основания: requirements UI/PROFILE/THEME/
CARD/INPUT/MOOD/ANIM/HISTORY/STATS/SHORTS-005, DEC-013/015 и стабильный
[data/UI/API contract v1](data-api-contract.md). Прямое поручение разрешило каталог

## Фактически написано

- Production API — `by.bebuliby.chrona.ui.ChronaApp(state, dispatch)`, без создания
  production VM, Room/collector/network и без подстановки fixtures. Тема берётся из
  `state.preferences`. Только `DataMode.DEMO` показывает постоянный demo banner.
- Навигация **Сегодня → История → Привычки → Друзья**. Настройки — из верхнего
  правого меню имени/аватара. Back закрывает настройки/детали/друга, затем возвращает
  «Сегодня». Busy/notice отображают состояние ядра; UI не выдаёт dispatch за успех.
- Общие карточки, крупное actual/goal **одного** шрифта, эмоция справа в карточке и
  деталях. YouTube имеет отдельные красно-белые tokens. Unknown — «—», partial —
  измеренная часть с `≥` и явным пояснением, а не достоверный нулевой итог.
- Числовая запись ручной привычки за явный `DayKey`: BigDecimal, точка/запятая,
  допустимы 0 и значения больше цели, нет cap goal/9999, экспонента/отрицательные/
  нечисловые строки не отправляются. Форма создания отправляет `CreateManualHabit`
  с `ValueUnit("custom", <введённая единица>)`; UI не придумывает расписание/серию.
- **Shorts actual не редактируется даже при ошибочном `canEditActual=true`:**
  дополнительно проверяется `collectionMode == MANUAL`. Для друга редакторы и
  архивирование вообще не включены. Ядро обязано независимо защищать write layer.
- Детали: явная дата/zone, goal editor по `canEditGoal`, score/usage/streak с
  unavailable-причинами, интервалы начала/конца/длительности/качества и gaps только
  для чтения. Архив ручной привычки подтверждается и не называется удалением истории.
- Семь Canvas-лиц без ресурсов/новых библиотек: tears, very_sad, sad, neutral,
  smile, big_smile, stars. Их **выбирает core**, не UI. Один короткий reveal по
  `valueCommit.eventId`, запоминаемый при recreation, затем
  `AcknowledgeValueAnimation`; collector ticks/recomposition не создают событие.
  `ValueAnimator.areAnimatorsEnabled()` и наблюдение системной animator scale
  отключают движение при системном reduce-motion. Нет бесконечной анимации/неона.
- Неделя — скруглённая таблица с закреплёнными названиями и 7 днями. Месяц —
  viewport 14 дней, **один** horizontal ScrollState/контейнер для header и body;
  слева названия неподвижны. Нет pager/snap. Подробности открываются из клетки.
- У Ready period score — непрерывная интерполяция исходного дробного score:
  muted burgundy 0 → yellow 50 → green 100. Контрастная black/white надпись
  выбирается по фону. q=1 — ✓, q=0 — ×, промежуточное — процент; очень малый/почти
  полный q не округляется в ложные 0/100. Unavailable не получает false-zero цвет.
- В **каждом** режиме истории есть «Статистика»: переданные проценты/числа,
  общая и индивидуальные cumulative curves, y=0 явно план, единица подписана.
  Общая — `plan_shares`, индивидуальная — единица привычки. UI не пересчитывает q,
  summary или кривые. Unavailable-точки **разрывают** path; нет сшивки через gaps.
  Ось нормализуется BigDecimal до Float, без переполнения на больших raw числах.
  Значения точек можно раскрыть текстом; дневные строки статистики — lazy.
- Год: переключатель/статистика и явная пометка **«Годовой вид ещё не выбран»**.
  Никакого самовольно выбранного heatmap.
- «Друзья»: сверху «Найти друзей», поиск/запросы/принятие/отклонение через actions,
  список и раскрытие только `FriendActivityUiState` accepted друга. Те же таблица,
  статистика, карточка, read-only интервалы/gaps. В disconnected состоянии даже
  ошибочно переданный fake список не показывается. Remote friend local URI не читается.
- Настройки: system/light/dark, палитры, стили, выбранное локальное фото, состояние
  tracking/Android permission, sync/last success/pending, Telegram login/status/logout
  через actions. Никаких credentials, сетевых логинов или скрытой выдачи разрешений.

## Дополнение: remote Telegram photo renderer

Root отдельно разрешил узкий image-fetch **только для отображения уже авторизованной
profile photo**, не business API/identity/storage. Domain и `ChronaApp(state, dispatch)`
не менялись. Дополнительная UI host-конфигурация, **не поле доменного контракта**:

```kotlin
// Только после review реального backend photo origin. Это документальный пример,
// не включённый адрес в production. Нельзя брать allowlist из ProfilePhoto.location.
val photoPolicy = remember {
    RemotePhotoPolicy(setOf("https://photos.chrona.example.org"))
}
CompositionLocalProvider(LocalChronaRemotePhotoPolicy provides photoPolicy) {
    ChronaApp(state, dispatch)
}
```

По умолчанию `RemotePhotoPolicy()` не разрешает ни одного origin. Пока backend
не подключён, root оставляет default и фиксирует настоящий sanitized photo endpoint
в общей backend-документации. INTERNET в manifest добавляет core при интеграции, не UI.
Endpoint должен возвращать **уже разрешённую** картинку по непарольному stable photo ID,
без bot token/bearer/session/signature в URL. Это не обещание private-photo auth через
неавторизованный GET: если endpoint требует bearer/cookie, business/core должен отдельно
решить получение разрешённого изображения, не передавать secret renderer-у.

Защита и ограничения:

- Exact allowlisted ASCII public DNS hostname, HTTPS/default443; никакого wildcard,
  arbitrary IP/localhost/local/internal, userinfo, query, fragment, percent encoding,
  traversal, backslash/control characters или token/auth/session/bot-number routes.
  `api.telegram.org` и Telegram bot-file URL запрещены даже при попытке allowlist.
- Перед соединением DNS выполняется в IO, все ответы проверяются на public-unicast:
  loopback/private/link-local/CGNAT/documentation/benchmark/multicast и local IPv6
  отвергаются. **Это не DNS pinning:** URLConnection резолвит hostname самостоятельно;
  allowlist обязан содержать только реально доверенный root-managed backend/CDN,
  не пользовательские/атакующие/rebinding origins. Политика не является универсальным
  SSRF sandbox для произвольных доменов.
- Никаких redirects, HTTP fallback, custom insecure TLS/hostname verification,
  credentials/cookies/request body или disk cache. При global CookieHandler/
  Authenticator либо невозможности проверить authenticator state старой платформы
  fetch fail-closed. Настоящие URL и exception messages нигде не логируются.
- Вся DNS/URLConnection/read/Bitmap работа — Dispatchers.IO. Connect/read timeout3с,
  coroutine budget12с и streaming deadline8с; cooperative cancellation проверяется
  в loop, connection закрывается finally. Синхронный OS DNS не даёт жёсткой wall-clock
  гарантии12с; это не объявлено измеренной сетевой latency/cancellation acceptance.
- Только status200 и JPEG/PNG/WebP, identity Content-Encoding; максимум2MiB и при
  известном Content-Length, и реально прочитанных байтах. Bounds до8192по стороне/
  32M исходных пикселей, downsample и повторная проверка decoded bitmap≤512×512.
  SVG/GIF/HTML/error body не рисуются. Нет gallery scan/auto-upload/новых пакетов.
- Memory-only LRU≤12 URL/8MiB, общая для аватаров одного ChronaApp: cache/serialized
  load дедуплицирует top-bar/settings. УспехTTL5мин, failureTTL30с; повтор после TTL
  только при новом запросе/remount, без polling/retry loop. Cache очищается при
  disposal/смене profile/account/binding/policy. Старый bitmap не вспыхивает при
  смене URI/аккаунта. Persistent image storage не добавлен.
- Loading/error/blocked состояния показывают placeholder и доступное текстовое
  описание (ошибка с «!»), без URL/secret деталей. Local chosen content URI работает
  прежним отдельным путём. Friend remote photo дополнительно требует текущий
  `CONNECTED` и реальный linked профиль; friend local URI никогда не открывается.

## Follow-up после интеграции `0502275`: настройка сервера и ручное согласие sync

`0502275` уже интегрирован с core; Android assembleDebug/test APKs/unit60+8/lint

не собственный Gradle-прогон этого follow-up. VM/context правит отдельно root.

UI использует обещанные **core-owned additions**, не создавая своей копии domain:

```kotlin
data class ConnectionUiState(val baseUrl: String = "", val loginPending: Boolean = false)
// Последнее default-поле ChronaUiState:
val connection: ConnectionUiState = ConnectionUiState()
// Action:
ChronaAction.ConfigureServer(baseUrl)
```

### Реализовано в этом малом diff

- В настройках рядом с профилем — публичный HTTPS base URL, явное сохранение через
  ConfigureServer, not-configured/pending/offline/error/confirmed тексты по текущему
  `connection`, `profile`, `sync`. Ошибки ядра по-прежнему показываются общим notice;
  UI не считает dispatch успешным сохранением или входом.
- Поле принимает только предварительно допустимый HTTPS URL без userinfo/query/
  fragment/токеновых маршрутов, очевидных localhost/IP/local hosts или traversal.
  ASCII host/default443/trailing slash нормализуются; обычный base path и явный
  HTTPS port допустимы на UI input-границе. Это **синтаксический guard**, не проверка
  DNS/публичного адреса/доверия/TLS или наличия backend — core валидирует повторно.
  Нет выдуманного адреса/автозаполнения реальным endpoint. Photo allowlist не строится
  из введённого base URL и этим follow-up не расширяется.
- Смена origin показывает подтверждение сброса входа/ожидающего login и поясняет,
  что токены не переносятся, локальные записи остаются. Production reset/persistence
  выполняет **core**, UI отправляет только ConfigureServer и ждёт новое state.
  Пароль/token-полей нет. Несохранённый/невалидный draft не используется для login;
  сам draft не попадает в rememberSaveable, URL/ошибки не логируются.
- BeginTelegramLogin остаётся единственным началом входа; пока loginPending,
  повторное начало отключено и доступен ручной RefreshLoginStatus. Logout — через
  action для привязанного профиля. Нет polling/авто-refresh/авто-sync effects в UI.
