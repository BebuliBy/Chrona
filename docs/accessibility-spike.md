# Первый эксперимент: AccessibilityService и YouTube Shorts

Статус: **базовый ручной проход завершён на SM-A376E/Android16/текущем YouTube**, не production-приёмка. Static contrast/предупреждение/lock/resume/чистый Home проверены; маленькое окно пользователь явно исключил(SHORTS-003/DEC-006). Ограничение active-root остаётся, другие focused/window modes не проверены. Mixed gaps/точность/battery/reboot и правило предупреждений не закрыты. [Отчёт](spike-results-2026-10-17.md).

## Минимальный объём

- Маленькое Kotlin-приложение с объяснением наблюдения, индикатором разрешения и локальными состояниями `SHORTS`, `NOT_SHORTS`, `UNKNOWN`.
- После явного включения пользователем — обработка только необходимых событий/структурных признаков официального YouTube. Для других пакетов не исследовать содержимое: достаточно признака ухода YouTube с переднего плана.
- Хранить локально только переходы состояния, времена/длительность, confidence/reason и gaps. Не сохранять названия/описания роликов, поиски, комментарии, clipboard, чаты, полные UI-деревья или скриншоты. Не собирать ключевые нажатия.
- Сначала проверить, какие минимальные стабильные признаки реально доступны. Если их нет — зафиксировать limitation, не переходить автоматически к screen recording/OCR/чтению другого контента/сетевому перехвату.
- Диагностика не отправляется на сервер/друзьям; никакой регистрации/bot/VLESS для этого proof не нужно. Не делать фоновый невидимый мониторинг и обход пользовательской остановки.

## Подготовка

Среда и project build готовы: AGP9.1.1, встроенный Kotlin, Gradle9.3.1 с проверенной Wrapper/distribution SHA256, JBR25, bytecode17. Prototype создан локально, без чужих templates. Это ограниченный эксперимент, не полномочия на весь продукт или сервер.

Текущий classifier использует candidate resource IDs `reel_recycler`, `reel_watch_fragment_root`, `reel_watch_player`, `reel_player_page_container`, `reel_player_view`, `reel_watch_fragment`. **Реально наблюдены `reel_player_page_container` и `reel_recycler`** на подтверждённом неподвижном Shorts,8/8замеров; в первой ordinary contrast-сцене оба отсутствовали. Другие режимы/версии ещё не проверены, остальные IDs гипотеза. Нижняя кнопка/полка Shorts не evidence. Без positive marker YouTube→UNKNOWN, не доказанный NOT_SHORTS. Другие пакеты не обходятся, lock/off/уход закрывают учёт. Polling1с/events — диагностика, не измеренная точность. UNKNOWN gaps не склеивать молча.

В последующем ordinary-контроле оба наблюдённых player IDs отсутствовали,8/8замеровUNKNOWN/без счётчика. Это первая contrast-сцена, не глобальная гарантия. `reel_time_bar` есть в обеих сценах — одиночным positive marker не использовать; код пока не менялся.

Для реальной проверки нужен телефон с доступным YouTube, USB debugging/RSA и добровольным включением сервиса. Разрешения пользователь выдаёт сам. Если Android блокирует sideloaded Accessibility, остановиться, объяснить ограничение и согласовать доверенный путь установки; защиты не обходить автоматически.

ADB подтвердил основной телефон **SM-A376E/Android16/API36**, One UI8.5 — сообщение пользователя; metadata YouTube21.41.525/factory20.41.40. Galaxy A33(2022) у друга, его ОС неизвестна. Первые структурные UI-признаки уже получены, язык и контролируемое сравнение пока не проверены. Фиксировать окружение каждого теста отдельно; эмулятор не заменяет реальное устройство.

## Матрица наблюдений

| Сценарий | Что проверяем |
|---|---|
| Home YouTube и обычный ролик | Нет ложного Shorts |
| Вход Shorts, переключение роликов, выход | Корректные переходы, нет необъяснимого разрыва внутри одного открытого экрана |
| Пауза на Shorts | Зафиксировать наблюдаемость и фактическую семантику открытого экрана; не выдавать её за playback |
| Back, другой tab, повторный вход | Правильное начало/окончание |
| Окно лимита Shorts0минут (сообщённый пользователем режим) | По отдельному подтверждению удержать открытым; проверить structural/state, не закрывать автоматически/не отключать лимит и не заполнять UNKNOWN без принятого правила |
| Home/другое приложение, screen lock/unlock | Счётчик не тянется по одному старому событию; содержимое другого приложения не собирается |
| PiP, multi-window, overlay/ad при наличии | Неизвестные состояния честно помечены; частные правила ещё согласуются |
| Отзыв/повторное включение Accessibility | Видимый статус/gap, нет обхода отказа |
| OS process death, reboot/unlock, user force-stop | Наблюдаемая восстановимость и ограничения отдельно; не обещать автооживление вопреки force-stop |
| Offline и повторное открытие prototype | Локальные уже записанные интервалы сохраняются; нет зависимости от bot/server |
| Переход суток/смена системных часов | Разделять timestamps и монотонную длительность; не придумывать финальную timezone policy в proof |

## Измерение и отчёт

Сравнивать переходы с ручной разметкой/таймером пользователя. Для каждого прогона: версии/сценарий, ручные времена, detector times, задержка входа/выхода, false positives/false negatives, unknown coverage, число повторов и наблюдённый расход ресурсов. Числовой порог приёмки и длительность нагрузочного теста заранее не утверждены — согласовать после первичных данных, не подбирать критерий задним числом ради pass.

Сборка/запуск сервиса ≠ распознавание Shorts; один успешный сценарий ≠ надёжный детектор. Возможные итоги: работает в явно описанных условиях; требует ограничений/следующей итерации; на этой версии признаков недостаточно. Во всех случаях обновить этот документ/roadmap/CHANGELOG с датой и доказательствами. Пользователь принимает следующий метод/изменение метрики отдельно.

## Основание

- [UsageStatsManager](https://developer.android.com/reference/android/app/usage/UsageStatsManager): не готовый Shorts-счётчик.
- [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService): платформенный механизм, наличие нужных YouTube-признаков не гарантировано.
- [Google Play Accessibility policy](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en): проверить отдельно при будущем Play-релизе; private APK не отменяет согласия/ограничений Android.
